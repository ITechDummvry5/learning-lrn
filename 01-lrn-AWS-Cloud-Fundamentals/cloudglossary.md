## Cloud Glossary

| Term                       | Simple Meaning                                                                 | Everyday Example |
|----------------------------|---------------------------------------------------------------------------------|------------------|
| **Low Latency**            | Very fast response time (almost no delay)                                       | Talking to someone sitting next to you |
| **Scalability**            | Ability to easily increase or decrease resources                                | A restaurant that can quickly add more tables when more customers come |
| **Elasticity**             | Automatically scales up or down based on demand                                 | An escalator that starts moving only when people step on it |
| **High Availability**      | System stays online most of the time with minimal downtime                      | A shop that almost never closes |
| **Minimal Downtime**       | The system is offline for a very short time (or almost never)                   | A shop that closes for only 5 minutes for cleaning |
| **Fault Tolerance**        | System continues working even if something fails                                | A car that can still drive if one tire gets damaged |
| **Reliability**            | System works correctly and consistently                                         | A clock that always shows the right time |
| **Agility**                | Ability to quickly make changes and innovate                                    | Changing a recipe in minutes instead of days |
| **Pay-as-you-go**          | Pay only for what you actually use                                              | Paying for electricity only for the hours you use it |
| **Region**                 | A physical location in the world where AWS has data centers                     | A city where a coffee shop chain has multiple branches |
| **Availability Zone (AZ)** | One or more data centers inside a Region, separated for safety                  | Different shops of the same coffee chain in different parts of the city |
| **Data Center**            | A building filled with servers that store and process data                      | The actual kitchen and equipment inside one coffee shop |
| **Failover**               | Automatically switching to another system when one fails                        | Customers going to another coffee shop when one shop is closed |
| **Redundancy**             | Having extra backup systems so nothing stops working                            | Having spare coffee machines in case one breaks |
